## 🗺️ Concept 1: Moving Boundaries
These programs teach you how to track indices that shift across a list, forming an active "window" or "zone" of focus.
## Problem 1.1: Fixed Window Slider

* The Goal: Calculate the sum of every adjacent pair of numbers in a list. [3] 
* Practice Requirements:
* Track two index variables: left (starts at 0) and right (starts at 1).
   * Run a loop where both indices increment by exactly 1 on each turn.
   * The loop must stop before right goes out of bounds. [4] 

## Problem 1.2: The Frame Scanner (Rolling Window)

* The Goal: Given a list and a size K, print out segments of the list that are exactly K items wide, moving from left to right.
* Practice Requirements:
* Establish a start boundary at 0 and an end boundary at K.
   * Slice the list using these boundaries (list[start:end]).
   * Increment both boundaries by 1 inside a loop until end hits the total length of the list. [5, 6] 

## Problem 1.3: Two-Pointer Wall Collapser

* The Goal: Check if a list of characters reads the same backwards as forwards (a palindrome), without using list[::-1]. [7, 8] 
* Practice Requirements:
* Place a left pointer at index 0 and a right pointer at the last index.
   * Compare the items at those two positions.
   * Move left forward by 1 and right backward by 1 on every turn, collapsing the boundaries inward. Stop the loop when they meet or cross. [9, 10] 

------------------------------
## 🧪 Concept 2: List Size Changes Dynamically
These programs force you to manage situations where deleting or inserting elements dynamically warps the size and indices of your list mid-execution.
## Problem 2.1: The Evens Purger

* The Goal: Remove all even numbers from a list in-place using a while loop (no secondary clean lists allowed). [11] 
* Practice Requirements:
* Set a manual index counter i = 0.
   * If list[i] is even, use del list[i] to remove it.
   * The State Trap: Because deleting an item shrinks the list and shifts everything left, your index i must not change if you delete an item. Only increment i += 1 if the item was odd and skipped. [12] 

## Problem 2.2: Dynamic Zero Duplicator

* The Goal: For every 0 found in a list, duplicate it right next to itself in-place, expanding the list size dynamically.
* Practice Requirements:
* Use a while loop with a tracking index i = 0.
   * When you encounter a 0, use list.insert(i, 0) to inject a duplicate.
   * Because inserting an item grows the list, you must advance your index by 2 steps (i += 2) after an insertion to jump past the newly added duplicate and avoid an infinite loop. [13] 

## Problem 2.3: In-Place Element Filter

* The Goal: Given a list of names, remove any name that has fewer than 4 characters, mutating the list directly.
* Practice Requirements:
* Track the changing size of the list manually inside a loop condition.
   * Ensure your loop condition evaluates the list's updated length (len(list)) dynamically on every iteration, rather than relying on a fixed range. [14, 15] 

------------------------------
## 🔄 Concept 3: Mapping Out the Changing States
These programs focus on tracking multiple interdependent variables as their conditions shift based on calculations. [16] 
## Problem 3.1: The Peak and Valley Tracker

* The Goal: Read a list of numbers representing temperatures and log whether each number is higher, lower, or equal to the previous day's temperature.
* Practice Requirements:
* Initialize a variable previous_state with the value of the first item.
   * Loop through the rest of the list starting from index 1.
   * At the end of every loop iteration, explicitly update previous_state = current_state to step forward cleanly. [17] 

## Problem 3.2: The Alternating Switch

* The Goal: Take a list of items and print them, but alternate the formatting (e.g., Row 1 is Upper Case, Row 2 is Lower Case, Row 3 is Upper Case). [18] 
* Practice Requirements:
* Create a boolean flag state variable: is_upper = True.
   * Inside your loop, read this state to determine your printing style.
   * At the bottom of the loop, invert the state variable using is_upper = not is_upper so the next turn behaves differently.

## Problem 3.3: Two-Speed Pointer Race

* The Goal: Find the exact middle element of a list in a single pass without using the len() function.
* Practice Requirements:
* Create two boundary pointers starting at index 0: a slow_pointer and a fast_pointer.
   * Run a loop where the slow_pointer advances by 1 step per turn, while the fast_pointer advances by 2 steps per turn.
   * Map out the state change: The moment the fast_pointer runs out of bounds, the slow_pointer will be standing exactly at the middle index. [19, 20]
