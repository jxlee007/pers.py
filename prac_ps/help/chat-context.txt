> "The user can write clean Python syntax independently but suffers from a severe gap in conceptual translation — converting problem statements into working programmatic logic."
> — Tutor Diagnosis

**The Gap Breakdown:**
1. **Logic Inversion** (~80% error rate)
   - Writes operations that do opposite of requirements
   - Example: Divides by percentage instead of multiplying
   
2. **Flawed Loop Conditions** (~70% error rate)
   - Writes conditions that never execute or crash
   - Example: `while balance == target` (should be `while balance < target`)

3. **Variable Scope Blindness** (~75% error rate)
   - Resets persistent variables inside loops
   - Example: `attempts = 0` inside while loop instead of outside

4. **No Flow Mapping** (~90% error rate)
   - Jumps into code without tracing execution
   - Writes code that LOOKS complete but is structurally broken

### Problem-Solving Workflow (For Each Problem)

```
Step 1: Identify Nouns (What data do we track?)
        Examples: User, Email, Account, Book, Task
        → Goes to models.py

Step 2: Identify Verbs (What operations do we perform?)
        Examples: send, validate, calculate, filter
        → Goes to business_logic.py

Step 3: Map the Flow (How does the main loop orchestrate?)
        Examples: Get user choice → Instantiate model → Call method
        → Goes to main_engine.py

Step 4: Code each layer independently
        Models: Just __init__ and attributes
        Logic: Methods that mutate/access data
        Main: User input loop that calls methods

Step 5: Test end-to-end
        Does it solve the original problem?
```
