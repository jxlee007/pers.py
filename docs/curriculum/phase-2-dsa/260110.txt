Big O notation gives us 
the idea about the efficiency of how much our code performance would be with n input size   
        
rank by fast
    1. O(1) = constant time
        no matter how big input size is
        eg  
        - accessing an specific index in an arr
        - check if elem exist in set
    
    2. O(log n) = logarithmic time
        where we divide the problem in half each time
        eg 
        - binary search

    3. O(n) = linear time
        going through each item once using loop
        eg
        - traversing through list
    
    4. O(n log n)
        it relate to sorting with sort methods

    5. O(n2) = IMP
        not a viable solution for large input as it too slow 
        almost always related to nested loop
        eg
        - brute force comparison

Note/Thumb-rule 
    for input   10 5 - O(n log n)
                10 4 - O(n2)
