## 🛠️ The "Self-Correction" Routine: How to Stay on Track Without an Evaluator
To progress without constantly needing someone to review your track, you must switch from a "Completion Mindset" (checking off a video) to an "Invariant State Mindset" (proving code accuracy). Follow this strict diagnostic checklist for every script you write:
## 1. The "Print-Tracing" Rule (Bypass Python Tutor)
Instead of copying your code to external visualization sites when it fails, become your own compiler inside your script. Print your working variable states inside loops:

# If your loop isn't doing what you want, drop this exact print template inside it:
print(f"[DEBUG] Index: {idx} | Current Value: {num_list[idx]} | List State: {num_list}")

Forcing yourself to look at variable states directly in your terminal output bridges your logical gap faster than any automated visualizer.
## 2. The 3-Point Edge-Case Battery
Before you declare a problem "solved," you must manually force your function to handle these three test inputs:

* The Zero/Empty State: What happens if the input is 0, "", or []? (Does it crash with an error, or exit gracefully?).
* The Single-Element State: What happens if your list has exactly one item? (Loops often break here if boundaries are hardcoded).
* The Out-of-Bounds/Negative State: What happens if someone inputs a negative number or a value outside your intended options?.
